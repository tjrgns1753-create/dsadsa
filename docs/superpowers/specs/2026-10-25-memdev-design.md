# memdev 설계: DRAM·NAND 소자 모델링과 비교 분석 도구

작성일: 2026-10-25
상태: 설계 검토 중 (구현 전)

## 1. 목적

- **대상 독자**: 반도체 기업 면접관(취업 포트폴리오), 그리고 작성자 본인(학습).
- **목표**: DRAM과 NAND 플래시를 소자 수준에서 모델링하고, 두 소자의 물리적 차이가 메모리 계층(DRAM 캐시 + NAND 용량)의 이유가 되는 과정을 숫자와 그래프로 보여 준다.
- **성공 기준**
  1. 모든 그래프와 수치를 작성자가 면접에서 "왜 이 식인가, 왜 이런 경향인가"까지 설명할 수 있다.
  2. 모델 결과가 공개 자료의 경향과 맞는지 자동 테스트로 확인되고, 맞지 않는 부분은 검증 문서에 이유와 함께 기록된다.
  3. AI 해설의 수치가 모델 계산 결과와 일치하는지 자동 검증되고, 그 효과(검증기 켬/끔 비교)를 수치로 보여 준다.

## 2. 범위

### 포함
- DRAM 모듈: 1T1C 셀의 저장·읽기, 누설 성분 분해, 리텐션, 리프레시, 셀 산포와 수율
- NAND 모듈: 셀과 Vth, FN 터널링, ISPP, 열화와 보존(P/E, retention, read disturb, 셀 간 간섭), RBER
- 비교 모듈: 두 소자를 같은 축에서 비교, 캐시 적중률–평균 접근 시간의 간단한 계산
- AI 해설 모듈: 계산 결과만을 근거로 한 해설과 수치 검증기, 평가 세트
- 노트북 3개, 개념 노트, 면접 Q&A, 검증 문서, README

### 제외 (후속 선택 단계)
- 웨이퍼맵 불량 패턴 분석(WM-811K)
- DEVSIM 등 TCAD 교차 검증
- MQSim 확장, 메모리 모드 시스템 시뮬레이션
- 로우해머, 센스앰프 회로 내부, ECC·FTL·컨트롤러, 재읽기 최적화, 3D NAND 층별 편차
- 앱·UI 개발, Verilog·회로 설계

## 3. 모델링 원칙

1. **컴팩트 모델**: 교과서·논문의 해석적 식을 사용한다. TCAD 수준의 구조별 정밀 수치는 다루지 않는다.
2. **절대 수치를 주장하지 않는다**: 누설과 보존 특성은 구조와 공정에 따라 자릿수로 달라진다. 이 도구가 주장하는 것은 (a) 구조 변수에 대한 민감도, (b) 조건별 지배 메커니즘, (c) 트레이드오프다.
3. **구조 변수 분리**: 구조·공정 변수를 코드 안에 숨기지 않고 명시적 입력으로 둔다. 각 변수가 어떤 메커니즘에 영향을 주는지 표로 연결한다.
4. **기준 구조 표시**: 모든 그래프에 사용한 구조 프리셋과 파라미터를 표시한다.
5. **파라미터 출처**: 모든 파라미터는 `params/` 아래 표에 값, 단위, 범위, 출처를 기록한다. 출처를 확인하지 못한 값은 `unverified`로 표시하고, 결과 문서에도 그 사실을 드러낸다.
6. **시뮬레이션 표시**: 모델이 생성한 데이터에는 항상 "시뮬레이션"이라고 표시한다.
7. **계산은 코드, 해설은 LLM**: LLM은 수치를 계산하지 않는다.
8. **실측 데이터 입력 경로**: 분포를 다루는 분석(DRAM 리텐션 분포, NAND Vth 분포와 RBER)은 모델 생성 데이터 외에 CSV(셀별 값 한 열)도 입력으로 받는다. 실측 데이터가 생기면 같은 분석을 그대로 적용할 수 있게 하기 위함이다.

## 5. DRAM 모듈

### 답할 질문
1. 저장한 전하는 얼마나 오래 읽을 수 있는 상태로 남는가?
2. 온도와 용량에 따라 리프레시 부담이 커지는 이유는 무엇인가?
3. 약한 셀이 수율과 리프레시 주기를 어떻게 정하는가?

### 모델
| 단계 | 내용 | 핵심 식 (개념) |
|---|---|---|
| ① 저장과 읽기 | 셀 커패시터 Cs에 전하 저장, 읽기 시 비트라인 Cbl과 전하 분배 | ΔV = (Vcell − Vdd/2) · Cs/(Cs+Cbl) |
| ② 누설 | 서브스레숄드(DIBL 포함), 접합(SRH 생성), GIDL(밴드 간 터널링), 유전체(선택)를 분리 | I_leak = Σ 성분, 성분별 온도·전압·구조 의존 |
| ③ 리텐션 | ΔV가 센스앰프 최소 마진 아래로 떨어지는 시점 | t_ret ≈ Cs·(V0 − V_min) / I_leak (일정 전류 근사, 필요 시 시간 의존 적분) |
| ④ 리프레시 | 주기 내 전체 행 재기록 부담 | 오버헤드 ≈ tRFC / tREFI |

### 산포와 수율
- 셀 누설(따라서 리텐션)은 본체 로그정규 분포와 약한 꼬리 성분의 혼합으로 모델링한다.
- 칩의 셀 수 N, 리프레시 주기 T에 대해 리텐션 < T인 셀 수를 구하고, 예비 셀 수리 한도를 넘으면 불량 칩으로 본다.
- 리프레시 주기 ↔ 수율 ↔ 리프레시 오버헤드의 트레이드오프 곡선을 만든다.

### 구조 변수와 프리셋
- 변수: 채널 길이, 채널 도핑, 게이트 산화막 두께, 접합 깊이와 도핑, 게이트–드레인 겹침, Cs, Cbl, 워드라인 꺼짐 전압, 트랩 밀도
- 프리셋: 평면형, 리세스 채널, 매립 워드라인. 프리셋별 특징은 공개 문헌으로 확인해 근거를 단다. 확인 전에는 `unverified`.

### 그래프
1. 셀 전압 감쇠와 센싱 마진 vs 시간 (온도별)
2. 누설 성분별 vs 온도 (지배 성분 전환 구간 표시)
3. 워드라인 꺼짐 전압 vs 누설 (서브스레숄드 감소와 GIDL 증가의 U자 곡선, 최적점)
4. 구조 변수 민감도 (토네이도 차트 등)
5. 리텐션 vs 온도, 온도별 필요 리프레시 주기
6. 리텐션 분포 (본체 + 꼬리, 셀 수 기준)
7. 수율 vs 리프레시 주기, 밀도별 리프레시 오버헤드

## 6. NAND 모듈

### 답할 질문
1. 전하를 넣고 빼는 원리는 무엇이고 왜 정밀 제어가 필요한가?
2. 셀당 비트 수가 늘면 왜 신뢰성이 급격히 나빠지는가?
3. 쓰기, 시간, 읽기가 각각 왜 데이터를 틀어지게 하는가?
4. 구조 변수들은 무엇을 맞바꾸는가?

### 모델
| 단계 | 내용 | 핵심 식 (개념) |
|---|---|---|
| ① 셀과 Vth | 저장 전하가 Vth를 이동. 플로팅게이트와 전하트랩을 구조 변수로 구분 | ΔVth = −Q / C_결합 |
| ② 터널링 | 터널 산화막 FN 터널링 | J = A·E²·exp(−B/E) |
| ③ ISPP | 단계 전압 프로그램과 검증. 정상 상태에서 펄스당 Vth 이동 ≈ ΔV_step | 분포 폭 ≈ ΔV_step + 잡음 |
| ④ 열화와 보존 | P/E에 따른 트랩 생성과 SILC, 보존 중 전하 손실(아레니우스), read disturb(Vpass 스트레스), 셀 간 간섭(결합) | 트랩 ∝ 사이클^α, 손실 ∝ log(t) |
| ⑤ RBER | 레벨 분포와 읽기 기준전압에서 겹침 면적 | 가우시안 꼬리(Q 함수) 또는 샘플링 |

### 구조 변수
터널 산화막 두께, 결합비, 트랩 밀도, 프로그램 스텝 ΔV, 셀당 비트 수(SLC/MLC/TLC/QLC)

### 그래프
1. FN 전류밀도 vs 전계, 프로그램 속도 vs 전압
2. ISPP 펄스별 Vth 이동, 분포 폭 vs 스텝 크기
3. TLC 8레벨 분포: 새 것 / 사이클 후 / 보존 후 겹쳐 보기, 읽기 기준전압 표시
4. RBER vs P/E 사이클, RBER vs 보존 시간·온도
5. read disturb: 읽기 횟수 vs 소거 상태 Vth
6. 트레이드오프: 터널 산화막 두께 vs (프로그램 속도·전압, 보존·내구성), 셀당 비트 수 vs 마진

## 7. 비교 모듈

| 항목 | 코드가 계산하는 것 |
|---|---|
| 저장 전자 수 | Q = C·V에서 전자 개수 (DRAM 셀 vs NAND 레벨 간 차이) |
| 전하 보존 시간 | 온도별 보존 시간을 한 로그 그래프에 |
| 쓰기 방식 | 쓰기 시간·전압 |
| 쓰기 대가 | 사이클 vs 열화 (DRAM은 실질적 무제한으로 표시) |
| 읽기 영향 | DRAM 파괴적 읽기 후 재기록, NAND read disturb |
| 계층 | 캐시 적중률 vs 평균 접근 시간 (식 한 줄 수준) |

결과물: 한 장짜리 비교 그림, 비교 표, 결론 한 문단("DRAM 캐시 + NAND 용량" 계층의 소자적 이유).

## 8. AI 해설 모듈

### 흐름
```
질문 → (LLM 또는 규칙) 분석 함수와 파라미터 선택 → 코드 계산 → 결과(숫자에 ID 부여, 그래프)
     → 해설 작성 (수치는 결과 ID로만 인용) → 검증기 대조 → 불일치 시 재시도(최대 2회) 후 경고 표시
```

### 규칙
- 해설에 등장하는 모든 수치는 결과의 특정 ID와 대응해야 한다. 대응이 없거나 값이 허용 오차를 벗어나면 불일치로 판정한다.
- 계산 근거가 없는 물리 설명은 "개념 설명(계산 아님)"으로 구분 표시한다.
- 기본값은 템플릿 해설(LLM 없음)이다. API 키(`ANTHROPIC_API_KEY`)가 있으면 LLM 해설을 켤 수 있다. 테스트는 LLM 없이 통과해야 한다.

### 평가
- 질문 약 20개와 기대 사실(관련 결과 ID) 세트를 둔다.
- 지표: 해설 수치 일치율, 불일치 탐지율.
- 비교: LLM 해설에 대해 검증기 켬/끔.

## 9. 테스트와 검증

| 종류 | 내용 |
|---|---|
| 물리 불변식 | 온도 상승 시 누설 증가, 단위 일치, 전하 분배에서 전하량 보존, 확률 합 1 등 |
| 경향 검증 | 누설의 아레니우스 형태, ISPP 분포 폭과 스텝의 비례, 보존 손실의 log(t) 의존, 사이클 증가 시 분포 확대, 높은 레벨일수록 큰 손실 등. 테스트마다 출처 기재, 미확인은 `unverified` 표시 |
| 해설 | 검증기 단위 테스트 (일치, 불일치, 근거 없는 수치 사례) |

- 난수는 시드를 고정해 재현성을 보장한다.
- 구현은 경향·불변식 테스트를 먼저 작성하는 TDD로 진행한다.
- 검증 문서는 `경향 | 근거 출처 | 모델 결과 | 일치/불일치 | 이유` 표로 정리하며 불일치도 기록한다.

| 위험 | 대응 |
|---|---|
| 이 환경의 네트워크 제한으로 논문·파라미터 출처 확인이 막힘 | 해당 값을 `unverified`로 남기고 작성자가 도서관 등에서 확인 |
| 컴팩트 모델의 단순화로 일부 경향이 맞지 않음 | 검증 문서에 불일치와 이유 기록, 필요하면 모델 보완 |
| 작성자가 물리 내용을 따라가기 어려움 | 단계별 개념 노트와 이해 확인 질문 |
| 범위 확대 | 2장의 제외 목록을 기준으로 새 요청은 후속 단계로 분류 |
| LLM 비용·키 부재 | 템플릿 해설을 기본값으로 둠 |

## 13. 결정 기록

- Verilog/회로 설계 방향 제외: 작성자가 디지털회로설계 미이수이고 소자 쪽을 원함.
- NAND 메인 메모리 시스템 연구(MQSim 확장) 제외: 목표가 소자 이해를 보여 주는 것이어서 핵심에서 제외하고 후속 선택으로 둠. MQSim 라이선스는 MIT로 확인함.
- 실측 데이터 없음: NAND·DRAM 셀 단위 원본 측정 데이터는 공개된 것이 거의 없어 모델 기반으로 진행하고, CSV 입력 인터페이스로 향후 실측 데이터 투입을 열어 둠.
- TCAD 미사용: 컴팩트 모델로 경향을 재현하고, TCAD 보정은 후속 단계로 둠.
