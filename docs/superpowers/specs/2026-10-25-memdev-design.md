# memdev 설계: DRAM 셀 소자 설계 프로젝트 (현업 방식 흐름)

작성일: 2026-10-25 (개정 2)
상태: 설계 검토 중 (구현 전)

## 1. 목적

- **대상 독자**: 반도체 기업 면접관(취업 포트폴리오), 그리고 작성자 본인(학습).
- **목표**: 현업의 소자 설계 흐름(스펙 → 소자 시뮬레이션 → 모델 추출 → 회로 확인 → 민감도 → 산포·최악 조건 → 최적화와 결정)을 따라 **DRAM 셀을 설계**하고, 마지막에 엔지니어링 질문 하나에 숫자로 답한다.
- **결론 질문**: "셀마다 리텐션이 다른데, 약한 셀이 있는 행만 자주 리프레시하고 나머지는 덜 자주 하면 리프레시를 얼마나 줄일 수 있고, 그 대가는 무엇인가?"
- **성공 기준**
  1. 작성자가 모든 단계에서 "무엇을 왜 했고, 결과가 무엇을 뜻하는가"를 면접에서 설명할 수 있다.
  2. 작성자가 Colab에서 파라미터를 바꾸면 결과가 바로 바뀌는 것을 확인할 수 있다.
  3. 각 단계의 결과가 교차 검증된다(손계산 vs 시뮬레이터, 컴팩트 모델 vs DEVSIM, 모델 경향 vs 공개 자료).
  4. 결론 질문에 대해 "리프레시 X% 감소, 대가 Y"라는 정량 결론과 그 한계가 문서로 남는다.

웨이퍼맵 분석(WM-811K), MQSim·메모리 모드 시스템 시뮬레이션, 로우해머, ECC·FTL, 공정(증착·식각) 시뮬레이션, 앱·UI 개발, Verilog.

## 3. 원칙

1. **현업과 같은 흐름, 다른 정밀도**: 방법론(스펙, DOE, 몬테카를로, 코너, 최적화)은 현업과 같게 한다. 상용 TCAD와 실제 공정 데이터가 없으므로 **절대 수치는 실제 제품에 쓸 수 없음**을 모든 결과에 밝힌다.
2. **주장의 범위**: 구조 변수에 대한 민감도, 조건별 지배 메커니즘, 트레이드오프, 설계 판단 과정.
3. **구조 변수 분리**: 구조·공정 변수는 명시적 입력으로 두고, 각 변수가 어떤 메커니즘에 영향을 주는지 표로 연결한다.
4. **파라미터 출처**: 모든 파라미터는 `memdev/params/` 표에 값, 단위, 범위, 출처를 기록한다. 확인하지 못한 값은 `unverified`로 표시한다.
5. **시뮬레이션 표시**: 모든 그래프에 "시뮬레이션"과 사용한 파라미터 세트를 표시한다.
6. **교차 검증**: 새 계산 도구를 쓸 때마다 손계산이나 다른 방법과 맞춰 본다.
7. **실측 데이터 입력 경로**: 리텐션 분포 분석은 모델 생성 데이터 외에 CSV(셀별 값 한 열)도 받는다.

### Colab 사용 방식
- 저장소는 공개(public)이므로 Colab이 GitHub에서 노트북을 직접 연다. 작성자는 파일을 업로드하지 않는다.
- 각 노트북의 첫 셀이 저장소를 내려받고, ngspice·BLAS(apt)와 DEVSIM·패키지(pip)를 설치하며, `DEVSIM_MATH_LIBS`를 설정한다.
- README에 노트북별 "Open in Colab" 링크를 둔다.
- 공개 저장소이므로 개인정보나 비공개 자료는 올리지 않는다.

### 상호작용 방식
- **가벼운 계산**(컴팩트 모델): 슬라이더를 움직이면 즉시 다시 그린다.
- **무거운 계산**(DEVSIM, ngspice, 몬테카를로): 입력 위젯으로 조건을 정하고 "실행" 버튼을 누르면 계산한다. 기본 조건의 결과는 노트북에 미리 저장해 두어 실행 없이도 보인다.

## 5. DRAM 셀 설계 흐름

### D1. 스펙 정의
현업 스펙 표 형식으로 목표를 정한다. 아래 값은 출발점이 되는 **가정**이며, 공개 자료로 근거를 찾으면 갱신한다.

| 항목 | 초기 목표 (가정) | 의미 |
|---|---|---|
| 리텐션 | 85°C에서 64 ms 이상 (예비 셀 수리 후, 칩 기준) | 리프레시 주기 안에 데이터 유지 |
| 읽기 신호 | 비트라인 신호 ≥ 50 mV | 센스앰프가 구분할 수 있는 최소 신호 |
| 쓰기 | 쓰기 펄스 10 ns 안에 셀 전압이 목표의 95% 도달 | 접근 트랜지스터가 충분히 켜짐 |
| 동작 조건 | 0~95°C, 전원 ±5% | 코너 검증 범위 |
| 수리 한도 | 칩당 수리 가능한 약한 셀 수 상한. 구체 값은 M1에서 공개 자료를 근거로 정하고, 근거를 못 찾으면 가정값으로 두고 D6에서 민감도로 다룬다 | 수율 판정 기준 |

### D2. 소자 시뮬레이션 (DEVSIM)
- **D2a (필수)**: 저장 노드 PN 접합의 역방향 누설. 1차원 구조에서 전압, 온도, 도핑, 캐리어 수명(트랩 밀도의 대리 변수)을 바꿔 가며 계산한다. SRH 생성 전류가 기본이며, 전계가 큰 조건의 트랩 보조 터널링은 가능하면 추가한다.
- **D2b (도전 과제)**: 접근 트랜지스터의 꺼짐 누설(서브스레숄드, GIDL). 2차원 MOSFET 구조와 밴드 간 터널링 모델이 필요하다. 수렴 문제나 모델 구현이 막히면 컴팩트 수식으로 대체하고 그 사실을 기록한다.
- 결과물: 조건별 누설 표(sweep 데이터), 격자·수렴 조건 기록.

### D3. 모델 추출
- D2의 sweep 데이터에 컴팩트 누설 수식(접합: 공핍층 폭과 SRH 생성, 온도는 아레니우스 형태 / 트랜지스터: 서브스레숄드 지수식, GIDL 수식)을 맞춰 파라미터를 뽑는다.
- 결과물: 추출 파라미터 표, 맞춤 오차(조건별 상대 오차), 맞지 않는 영역의 기록.

### D4. 회로 확인 (ngspice)
- 회로: 접근 트랜지스터 + 셀 커패시터(Cs) + 비트라인 커패시턴스(Cbl) + 간단한 래치형 센스앰프. 셀 누설은 D3 컴팩트 모델을 전압 제어 전류원으로 넣는다. 트랜지스터는 ngspice 내장 MOSFET 모델에 가정 파라미터를 쓴다.
- 측정: 쓰기 후 경과 시간별 비트라인 신호, 센싱 성공 여부, 쓰기 시간.
- 교차 검증: 회로 결과의 리텐션과 컴팩트 모델 계산(전하 분배식)을 비교한다.

### D5. 민감도 분석 (DOE)
- 변수: 접합 도핑, 캐리어 수명(트랩 밀도), Cs, Cbl, 워드라인 꺼짐 전압, 게이트 산화막 두께, 채널 도핑(D2b 성공 시).
- 방법: 한 번에 하나씩 바꾸는 분석으로 시작해, 주요 변수는 요인 설계나 라틴 하이퍼큐브 샘플링으로 상호작용을 본다.
- 결과물: 토네이도 차트(어떤 변수가 리텐션을 가장 좌우하는가), 워드라인 꺼짐 전압 vs 누설 U자 곡선(D2b 또는 컴팩트 수식 기반).

### D6. 산포와 최악 조건
- **몬테카를로**: 공정 변수에 분포를 주어 셀 수십만~수백만 개를 샘플링하고, 리텐션 분포(본체 + 약한 꼬리)를 만든다. 칩 규모(수십억 셀)의 꼬리는 분포 맞춤으로 외삽한다.
- **코너**: 온도 0~95°C, 전원 ±5%의 조합에서 스펙 만족 여부를 확인한다.
- 결과물: 리텐션 분포, 리프레시 주기 vs 수율 곡선, 코너 표.

### D7. 최적화와 결정 (결론 질문)
- 스펙(D1)을 모든 코너와 수율 조건에서 만족하는 설계안을 고르고, 선택 이유와 트레이드오프를 표로 남긴다.
- **결론 질문 분석**: D6의 리텐션 분포로 행을 리텐션 구간별로 나누고(예: 64 ms / 128 ms / 256 ms 그룹), 구간별 리프레시 주기를 적용했을 때 리프레시 횟수 감소율을 계산한다.
- 대가로 다음을 정량 또는 정성으로 평가한다: 구간 정보 저장 비용, 리텐션 측정(프로파일링)의 불확실성, 시간에 따라 리텐션이 변하는 셀(VRT)의 위험, 온도 변화 대응.
- 이 아이디어는 기존 연구(RAIDR 등)가 제안한 것이며, 이 프로젝트는 그 효과를 자신의 셀 모델로 재현하고 조건을 바꿔 보는 것임을 명시한다.

## 7. 테스트와 검증

| 종류 | 예 |
|---|---|
| 물리 불변식 | 온도 상승 시 누설 증가, 전하 분배에서 전하량 보존, 단위 일치, 확률 합 1 |
| 교차 검증 | ngspice RC 감쇠 vs 해석해, DEVSIM 접합 누설 vs SRH 공핍층 공식(자릿수), 컴팩트 모델 vs DEVSIM 맞춤 오차 한도, 회로 리텐션 vs 컴팩트 리텐션 |
| 경향 | 누설의 아레니우스 형태, 역방향 전압 증가 시 접합 누설 증가, 리텐션 분포의 꼬리 형태. 출처 기재, 미확인은 `unverified` |
| 수치 품질 | DEVSIM 격자 세분화 시 결과 변화가 허용 범위 이내 (현재 시험 결과에서 0 V 잔류 전류와 저전압 순서 역전이 보이므로 M2에서 해결) |

- 난수 시드 고정, DEVSIM·ngspice가 없는 환경에서는 해당 테스트를 건너뛰고 그 사실을 출력한다.
- 구현은 테스트를 먼저 쓰는 방식(TDD)으로 진행한다.
- 검증 문서: `항목 | 기준(출처 또는 해석해) | 결과 | 일치/불일치 | 이유`.

| M2b | D2b 2D MOSFET 누설 (도전 과제) | 성공 시 D3~D5에 반영, 실패 시 대체 기록 |

- 각 단계는 독립된 결과물이며 어디서 멈춰도 쓸 수 있다.
- 각 단계가 끝나면 Colab 링크를 전달하고, 작성자의 이해를 확인하는 질문을 거친다.

## 9. 2단계 개요: NAND 셀 설계

1단계와 같은 흐름(스펙 → 소자 → 추출 → 회로·분포 → 민감도 → 산포 → 결정)을 NAND에 적용한다. 다룰 물리는 셀 Vth와 결합비, FN 터널링, ISPP, P/E 열화와 SILC, 보존 중 전하 손실, read disturb, 셀 간 간섭, 레벨 분포와 RBER이다. 설계 변수 후보는 터널 산화막 두께, 결합비, 프로그램 스텝, 셀당 비트 수다. 결론 질문 후보: "열화에 따라 읽기 기준전압을 옮기면 RBER을 얼마나 줄일 수 있는가?" 상세 설계는 1단계 완료 후 작성한다.

## 10. 3단계 개요: 비교와 AI 해설

- 비교: 저장 전자 수, 보존 시간, 쓰기 방식과 대가, 읽기 영향을 같은 축에 놓고 메모리 계층(DRAM 캐시 + NAND 용량)의 소자적 이유를 설명한다.
- AI 해설: LLM은 계산하지 않고, 해설의 수치는 계산 결과 ID로만 인용하며, 검증기가 대조한다. 템플릿 해설을 기본값으로 두고 API 키가 있으면 LLM 해설을 켠다. 평가 세트로 검증기 켬/끔 효과를 측정한다.
- 상세 설계는 2단계 완료 후 작성한다.

## 12. 결정 기록

- Verilog/회로 설계 방향 제외: 작성자가 디지털회로설계 미이수이고 소자 쪽을 원함.
- MQSim 확장 제외(후속 선택): 목표가 소자 이해와 소자 설계. MQSim 라이선스는 MIT로 확인함.
- 실측 데이터 없음: 셀 단위 원본 측정 데이터는 공개된 것이 거의 없어 모델·시뮬레이션 기반으로 진행.
- 개정 2의 변경 사항
  - 시험작(DRAM 셀 누설 그래프)에 대해 "교육 자료에 그친다"는 지적이 있었고, 원래 계획에 결론이 없다는 약점을 인정해 결론 질문을 추가함.
  - 작성자 요구: 파라미터를 바꿔 결과를 확인할 수 있을 것, 현업과 유사한 방식으로 소자 설계까지 갈 것.
  - DRAM을 먼저 설계까지 진행하고 NAND는 같은 흐름으로 이후에 진행.
  - TCAD 대용으로 DEVSIM, 회로 확인용으로 ngspice 채택. 두 도구 모두 개발 환경과 Colab에서 실행 확인.
  - 실행 환경은 Colab, GitHub 공개 저장소에서 직접 열기로 결정.
